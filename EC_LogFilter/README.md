# EC_LogFilter

在游戏内查看各日志来源的数量，按来源独立屏蔽 Debug、Info、Message、Warning、Error、Fatal。

版本：1.0.0。适用于 Emotion Creators / BepInEx 5。

## 使用

1. 将编译后的 **EC_LogFilter.dll** 放入游戏的 BepInEx/plugins 目录或其子目录。不要复制构建用的 BepInEx、Harmony、Unity 依赖。
2. 启动游戏，按 **Ctrl+Alt+L** 打开或关闭窗口。
3. 在左侧选择日志来源，在右侧勾选要屏蔽的等级。**[x] 表示屏蔽，[ ] 表示放行**，默认全部放行。
4. 可按名称筛选，或按累计数量、已屏蔽数量、名称排序。鼠标停留在列表或正在拖动时，列表暂不重排，数字仍会刷新。
5. “全部勾选”和“全部取消”上下分两行，仅修改选中来源；“暂停屏蔽”对全部来源临时放行，保留规则、继续计数。再次点击恢复过滤。

关闭窗口不会停止统计或过滤。窗口可以通过标题栏拖动，位置在拖动结束后保存。

## 统计口径

- 以 BepInEx 提供的**原始 SourceName** 分组，不通过调用栈猜测插件归属。同名来源共用规则；大小写、前后空格不同的名称分别统计。
- 来源通常对应插件，但一个插件可能有多个来源，也可能与其他插件同名。
- 从本插件安装日志拦截后开始计数，不补算此前的启动日志；每次启动游戏重新计数。
- 累计数量包含已屏蔽事件。六等级分别计数，多等级事件会进入多个分项，因此分项之和可能大于累计数量。
- 组合等级必须全部被勾选才会屏蔽。例如只屏蔽 Info 时，Info | Error 仍放行。None 和含未知位的等级始终放行。
- 规则已保存、但本次还没打印日志的来源也能管理，详情显示“本次尚未出现日志”。
- 数字约每秒刷新一次；规则点击后立即作用于后续日志，不必等待数字刷新。
- 不保存日志正文，不回读日志文件。窗口关闭时不生成显示快照。

## 规则保存

固定路径位于**游戏根目录**：

    UserData\PluginData\EC_LogFilter\rules.xml

只保存非空屏蔽规则，不保存统计数字或本次暂停状态。连续修改结束约 0.5 秒后保存，正常退出时补存；异常终止可能丢失最后约 0.5 秒的修改。

示例：

    <?xml version="1.0" encoding="utf-8"?>
    <LogFilterRules Version="1">
      <Rule Source="ExamplePlugin" Blocked="Info Debug" />
    </LogFilterRules>

临时文件 rules.xml.tmp.* 和上一版备份 rules.xml.bak 也在该目录。已有文件通过替换保存，不先删除旧文件。

### 文件出错时

- **读取失败**：保留原文件，本次先全部放行；窗口内修改仍生效，但仅在本次运行有效，不自动覆盖旧文件。备份并修复或移走问题文件后，重启游戏再使用自动保存。
- **保存失败**：旧文件保持不变，内存中的修改继续生效。窗口显示未保存，可排除路径占用或权限问题后点击“重试保存”。不会每帧重试；下一次修改和正常退出也会尝试保存。
- 规则区直接显示等待保存、已保存或失败状态，无需悬停；仅在错误状态上悬停时显示错误详情，保存失败仍可重试。即使屏蔽了本插件自己的日志，也能看到窗口状态。规则路径见本节，窗口不常驻路径说明。

## 常规配置

BepInEx/config/com.ec.logfilter.cfg 只保存快捷键和窗口位置，不重复保存来源规则：

| 配置 | 默认值 | 含义 |
|---|---|---|
| Window / ToggleShortcut | Ctrl+Alt+L | 打开或关闭窗口；左右 Ctrl/Alt/Shift 均可满足相应修饰键。 |
| Window / PositionX | 0.5 | 可用屏幕范围内的水平位置，0 为左，1 为右。 |
| Window / PositionY | 0.3 | 可用屏幕范围内的垂直位置，0 为上，1 为下。 |

## 边界

- 过滤作用于 BepInEx 统一入口到已注册监听器的分发，包括其文件和控制台监听器。
- **不会修改 BepInEx 原有的输出端等级**。某等级解除屏蔽后，仍可能因为控制台或文件本身的配置而不显示；放行数量不等于实际写入数量。
- 不保证过滤插件自行写入的文件、Unity 自己的原始日志、绕过统一入口的直接事件订阅。
- 无法撤销已经输出的日志，也无法消除其他插件在提交日志前的字符串拼接、数据准备，以及 BepInEx 本来就会创建的事件参数。
- 若其他日志插件更早截断了事件，本插件可能观察不到。自身拦截出错时停止本次过滤并放行；不会吞掉原有监听器自己抛出的异常。

## 构建与测试

在 EC_LogFilter.csproj 所在目录执行：

    dotnet build EC_LogFilter.csproj -c Release

默认输出路径相对于工程目录为 ../../bin/BepInEx/plugins/EC_LogFilter/；完整 DLL 路径见构建输出。

开发仓库中的同级 EC_LogFilter.Regression 目录提供独立回归与性能工具，不随插件源码镜像发布。该工具使用真实 BepInEx/Harmony DLL 在桌面 CLR 上验证日志接入，不代替游戏中的窗口与输入验收。

卸载时移走 EC_LogFilter.dll 即可；规则目录可保留。
