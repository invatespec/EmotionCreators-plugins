# EC_SceneAudit

`EC_SceneAudit` 在 HEdit Scene 中导出只读 JSON 证据快照，并可对网页修复清单进行原文预检和可恢复的内存文本写回，供节点可达性、Variable Mod 控制流和人工审查使用。

## 使用

- 默认快捷键：`F8`
- 配置文件：`BepInEx/config/EC_SceneAudit.cfg`
- 输出目录：`UserData/PluginData/SceneAudit/{SceneTitle}/{yyyyMMdd}/{批次目录}/`

### 修复预检（只读）

- 默认快捷键：`Ctrl+F8`（`Config` 段的 `Repair Preflight`）
- 仅在 HEdit 节点总览中打开；ADV/HPart 编辑、播放、加载或基础设置中不可预检。离开总览、重新打开窗口或修改路径都会清除旧结果。
- 窗口填写「修复清单」`ec-scene-repair-plan.json` 与对应的 F8 资料包目录，点「读取预检」。
- 路径可预填在配置文件 `Repair` 段的 `Plan Path` 和 `Bundle Directory`；点击读取时记住当前路径。原有导出快捷键配置保持不变。
- 结果逐项显示 Part/CUT/文本框/布局、原文是否一致和冲突原因，结论只表述为「原文一致」或「冲突」，不证明脚本运行结果。
- 「导出文字报告」在清单同目录写入 `*.preflight-<时间>.txt` 新文件，不改动清单、原 F8 或游戏数据。
- 报告记录该次检查时间与耗时。预检只比较原文和定位身份；不执行修改稿、不应用修复、不保存 Scene。

### 应用修复（内存快照，可恢复）

- 预检通过后点「应用修复（仅内存）」。窗口持续提示先手动保存：插件不写 Scene 文件，也不调用原生全量 Save/Load。
- 应用会重新读取清单与资料包并重新核验当前 Scene；来源、结构、UID/源序号或原文任一条冲突都不写回，内存不动。
- 应用前按清单目标 UID 记录受影响内存快照：目标 `ADVPart` 用原生 Save/Load 内存往返做独立深拷贝，目标节点保存完整 `NodeBase`，并记录所有指向目标的非目标来源入线槽位；目标之间互连不重复记录。
- 写回只改清单目标的 `ADVPart.SpeechBubbles.TextLayout.msg`，整批作为一次内存事务；任一目标无法唯一定位或写入异常就撤销本次内存改动。
- 成功后阶段为「已应用，未保存，待 F8 回验」：在游戏内按 F8 重新导出，再点「读取 F8 回验」核对每项新文、确认旧原文不再是当前文本，并比较未目标项的结构与文本。回验只接受本会话清单/资料包与应用之后的新批次。
- 回验不通过时保留内存结果、差异与快照，默认由作者点「恢复内存快照」处理，不自动覆盖；恢复只在 HEdit 节点总览内执行，先校验全部目标和连线端点，失败会尝试回滚并如实报告结果。
- 恢复只还原快照记录的目标 Part、目标 `NodeBase` 与相关入线槽位，未涉及节点保持原样。切换 Scene 或同路径重新加载后旧快照失效；「清除本次记录」只丢弃快照引用，已写入内存的文本改动仍保留，需要落盘请自行保存。

### 节点补丁与布局

网页「节点补丁」导出的文件在本窗口填写节点补丁路径及原 F8 资料目录后，依次执行「读取节点预检」「应用节点补丁（仅内存）」。插件只修改既有连接目标和补丁中的节点位置，不增删节点或选项，不自动保存 Scene。

布局采用新 F8 的实际节点几何。需要扩大画布时再次确认；只有支持动态扩展 API 的 EC_NodeSidePanel 才能扩展，无能力时整批拒绝。扩展是当前会话状态，恢复节点快照保留扩大的画布。文本修复与节点补丁不能同时持有有效恢复会话。

应用后重新 F8，再点「读取节点 F8 回验」。不满意时恢复节点快照；确认结果后由作者手动保存。第一份 Scene 已在游戏内实测：应用 1 个连接与 19 个位置后，新 F8 回验和内存恢复通过，恢复保留扩展后的画布。异常补偿、无扩展能力拒绝等边界目前只有离线回归覆盖。

### F8 导出内容

- 全部节点（含 `node_start` / `node_end`）和 5 个输出槽；
- 可用时附完整画布、节点矩形和相对端口几何；无法可靠采样时标明不可用，不猜测节点尺寸。
- 节点关联的 H/ADV Part；
- ADV Part 的 CUT、对白框源索引、显示层级排序和两个文本布局原文；
- `<script>` 原文、命令、属性、变量引用、跳转、事件、子脚本和外部脚本状态；
- 缺失节点、Part、目标、坏 XML、未知命令和外部脚本读取失败 warning。
- 同目录额外生成 `ai-summary.json`，仅包含 Scene 统计、Part 索引、变量读写、
  嵌套逻辑树、事件/跳转关系和静态 finding，不复制原始文本、脚本原文或普通对白全文。

`ai-summary.json` 的 `sourceEvidenceFile`、各项 `rawRef` 和 `sourceOffset` 可回查同目录完整证据 JSON。
合法 XML 脚本的 `parseStatus` 为 `valid` 并保留 `if`、动作、事件和跳转的嵌套顺序；
解析失败时为 `invalid`，只保留命令列表、warning 和来源定位，不生成推测逻辑树。

导出与预检流程不会执行脚本，也不会修改节点、Part、对白、变量或播放位置；内存写回只由作者触发「应用修复」或「应用节点补丁」并重新核验后执行，且不写文件。JSON 使用插件内置递归 writer 生成，schema 为 `1.0`。Scene 标题为空时，标题目录使用导出日期。

修复预检同样是只读流程：先核验清单来源与资料包 `bundle.json`/`bundle.sha256`/`scene` 成员哈希，再用当前 Scene 快照按 UID、CUT/文本框源序号和布局序号定位对照。清单最多 1000 项，单项新文最多 1,000,000 字符，`before` 必须逐字符等于资料包原文。

每次 F8 独立保存 `scene.json`、`ai-summary.json`、实际引用的外部脚本及 `bundle.json` 来源清单；`bundle.sha256` 最后写入。资料目录可整体移动，不依赖游戏盘符。同日导出不会覆盖上一批摘要。缺失、动态、范围外或限额依赖会记录原因；不会读取同目录无关脚本。

收集上限为单文件 2 MiB、合计 16 MiB、256 文件、32 层。若导出中途失败，已保存的完整证据保留；缺少清单校验文件的目录不可当作完整资料包。

## 交给 AI 审查

将 [ec-scene-review](ec-scene-review/SKILL.md) 整个文件夹交给 AI，并提供本次 F8 的整个资料目录。AI 按 skill 输出简短说明与 `review-report.json`，来源与引用可通过 [review-core](review-core/README.md) 校验。该 skill 包含游戏背景、静态审查流程、导出字段说明和 Variable Mod 文档，不依赖固定游戏路径。

可直接说：请先阅读 `ec-scene-review/SKILL.md`，按其中流程审查我提供的导出文件，说明问题位置、触发条件、证据和未验证范围。
