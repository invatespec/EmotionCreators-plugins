# EC_SceneAudit

`EC_SceneAudit` 导出 HEdit Scene 资料供网页和 AI 审查，并将匹配的文本修复、节点位置和连线补丁应用到当前游戏内存。

## 使用

- 默认快捷键：`F8`
- 配置文件：`BepInEx/config/EC_SceneAudit.cfg`
- 输出目录：`UserData/PluginData/SceneAudit/{SceneTitle}/{yyyyMMdd}/{批次目录}/`

### 应用修复与恢复

按 **Ctrl+F8** 打开修复窗口，在「文本修复」页填写网页导出的修复清单文件，点击「应用修复」。

- 匹配当前节点 UID、CUT/文本框源序号和布局序号后写入新文本。
- 当前原文与导出时不同也可以应用；缺失节点或文本项直接跳过，不影响其它项。
- 不需要原 F8 资料目录，不做预检或应用后的 F8 回验。
- 应用只改内存，不自动保存 Scene。需要保留结果时，在游戏里手动保存。
- 应用前保留目标 Part、节点和相关连线的独立内存快照。

### 节点补丁与布局

切到「节点补丁」页，填写网页导出的 `ec-scene-node-patch` 文件，点击「应用节点补丁」。

匹配到的节点位置和源槽连接会应用；缺失来源节点、目标节点或槽位直接跳过。已移动的节点、变化的旧连接以及补丁外新增的节点，都不会阻止其他修改。插件不增删节点或选项，连接只改目标，不覆盖当前条件参数。

画布需要扩大时沿用 EC_NodeSidePanel 的绝对尺寸扩展 API；没有该能力时仍应用节点，由游戏自身限制位置范围。恢复快照保留已经扩大的画布。

### 隐藏、重开与重复恢复

- 点击「隐藏」或按 Ctrl+F8，只隐藏窗口，不清除快照。
- 再按 Ctrl+F8 可以重新打开。两个页签各自保留最近一次应用前的快照。
- 「恢复内存快照」恢复当前页的快照，恢复成功后仍可以再次点击。
- 恢复时已删除的节点或连接端点会跳过，不重新创建节点。
- 新应用不受旧会话限制；同类新操作会更新快照。没有匹配项或文件读取失败时保留原快照。
- 切换 Scene 或重新加载后，旧快照不能用于新 Scene。应用和恢复都在 HEdit 节点总览执行。

路径在应用时保存到配置 `Repair/Plan Path` 或 `Repair/Node Patch Path`。
快捷键沿用 `Config/Repair Preflight` 配置键，旧配置无须调整；`Repair/Bundle Directory` 保留兼容，但不再参与应用。

### F8 导出内容

- 全部节点（含 `node_start` / `node_end`）和 5 个输出槽；
- 可用时附完整画布、节点矩形和相对端口几何；无法可靠采样时标明不可用，不猜测节点尺寸。
- 节点关联的 H/ADV Part；
- ADV Part 的 CUT、对白框源索引、显示层级排序和两个文本布局原文；
- `<script>` 原文、命令、属性、变量引用、跳转、事件、子脚本和外部脚本状态；
- 缺失节点、Part、目标、坏 XML、未知命令和外部脚本读取失败 warning。
- 同目录额外生成 `ai-summary.json`，仅包含 Scene 统计、Part 索引、变量读写、
  嵌套逻辑树、事件/跳转关系和静态 finding，不复制原始文本、脚本原文或普通对白全文。

`ai-summary.json` 的 `sourceEvidenceFile`、各项 `rawRef` 和 `sourceOffset` 可回查同目录完整证据 JSON。
合法 XML 脚本的 `parseStatus` 为 `valid` 并保留 `if`、动作、事件和跳转的嵌套顺序；
解析失败时为 `invalid`，只保留命令列表、warning 和来源定位，不生成推测逻辑树。

导出不会执行脚本或修改游戏数据。点击「应用修复」或「应用节点补丁」才修改当前内存，不写 Scene 文件。JSON 使用插件内置递归 writer 生成，schema 为 `1.0`。Scene 标题为空时，标题目录使用导出日期。

修复清单最多 1000 项，单项新文最多 1,000,000 字符。文件格式、字段类型和下标范围由 reader 解析；当前节点是否存在按项处理。

每次 F8 独立保存 `scene.json`、`ai-summary.json`、实际引用的外部脚本及 `bundle.json` 来源清单；`bundle.sha256` 最后写入。资料目录可整体移动，不依赖游戏盘符。同日导出不会覆盖上一批摘要。缺失、动态、范围外或限额依赖会记录原因；不会读取同目录无关脚本。

收集上限为单文件 2 MiB、合计 16 MiB、256 文件、32 层。若导出中途失败，已保存的完整证据保留；缺少清单校验文件的目录不可当作完整资料包。

## 交给 AI 审查

将 [ec-scene-review](ec-scene-review/SKILL.md) 整个文件夹交给 AI，并提供本次 F8 的整个资料目录。AI 按 skill 输出简短说明与 `review-report.json`，来源与引用可通过 [review-core](review-core/README.md) 校验。该 skill 包含游戏背景、静态审查流程、导出字段说明和 Variable Mod 文档，不依赖固定游戏路径。

可直接说：请先阅读 `ec-scene-review/SKILL.md`，按其中流程审查我提供的导出文件，说明问题位置、触发条件、证据和未验证范围。
