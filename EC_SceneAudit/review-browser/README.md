# Scene 审查网页

在本机选择 F8 资料包和审查报告,查看节点关系、问题位置和 CUT 全文,编辑并导出修复草稿。资料文件只在浏览器内读取;本机服务负责网页资源与数据目录读写,不改动原始导出目录。

## 启动

玩家侧:双击 `scene-review.exe`,控制台窗口打印本地网址(默认 http://127.0.0.1:18762),在浏览器打开该网址即可。只需要这一个文件,不需要安装 Node.js,不需要联网。关闭控制台窗口即停止服务。

从源码构建可执行文件需要 Node.js 22 与 Bun 1.3,在仓库根目录运行:

```powershell
npm --prefix plugin/EC_SceneAudit/review-core ci
npm --prefix plugin/EC_SceneAudit/review-browser ci
node plugin/EC_SceneAudit/review-browser/scripts/build.mjs --exe
```

产物为 `plugin/EC_SceneAudit/review-browser/release/scene-review.exe`(约 83 MiB);发布目录不需要 `dist/`、`node_modules/`,也不需要任何前端资源文件。

开发模式(改前端或服务端代码时)在仓库根目录运行:

```powershell
bun plugin/EC_SceneAudit/review-browser/server/main.mjs
```

端口与数据目录写在程序同级的 `config.json`(首次运行自动生成,字段说明见同目录 `config.README.txt`),也可以用命令行 `--port` / `--data-root` / `--config` 临时覆盖;优先级为命令行 > 配置文件 > 内置默认(端口 18762)。端口被占用时程序打印占用说明并以非 0 退出码结束,改用其它端口不需要重新编译。`scripts/serve.mjs` 是纯静态预览入口,没有 `/api/`,前端在它上面无法工作,不要用它启动网页。

1. 点击「资料与报告」，选择**直接包含 `bundle.json` 的单个 F8 导出目录**。浏览器原生选择框可能把选目录称为「上传」；选择只在本机读取,不写入原始导出目录。
2. 可选当前报告 JSON，以及它的前版 JSON。每次选择后自动核验；关闭导入窗口开始浏览。
3. 选择问题进入说明并定位；多个位置可逐个选择。共享外部脚本调用处使用空心标记，需选择具体调用位置。
4. 点击节点读取 CUT，滑条只覆盖该 Part。前后范围独立；到达边界后选择路线，点击 CUT 查看所有文本框和布局原文。
5. 输入 Part 名称搜索，支持忽略大小写和空白；点击候选或用 ↑↓ / Enter 跳转，Esc 关闭。搜索跳转沿用该 Part 的 CUT 阅读位置，保留当前问题说明。
6. 选择工具使用左键框选/成组移动节点、右键平移;按 H 切到平移,左右键都平移画布,按 V 恢复选择。输入文字或打开全文/导入窗口时不响应 H/V;停靠的编辑面板不算模态。Esc、切换模式或窗口失去焦点会取消拖动。滚轮缩放,布局保存到数据目录。
7. 顶部「编辑与补丁」是开关:点击打开统一面板,再次点击收起。面板桌面右侧停靠,可拖动调宽;窄屏在画布下方。各子页底栏(保存/导出/修复清单操作)默认隐藏,点面板顶部按钮展开。切页和收起不会丢草稿。排列菜单提供对齐基准、六种对齐、等间隔与吸附；工具有名称提示。

重新选择资料目录时,先清空旧的报告选择与问题标记,再核验新包。目录不完整时不显示旧图冒充新资料；报告失败时保留已核验资料，停用问题标记。修订版未提供前版时仍可阅读，提示 `history-unavailable`；提供前版后校验修订关系。前版可以来自同一 Scene 的旧导出批次：改完重新按 F8 后沿用旧报告，按问题 ID 核对修订关系，并提示 `previous-other-bundle`（旧引用未在新资料上复核）。撤销项在前版在场时可以只写 `id`、`status`、`revisionReason`，其余字段从旧报告补齐；补齐后的标题与理由照常显示在撤销区，项目里存的仍是 AI 写的原始报告。

布局和阅读默认范围按 `bundleId + manifestSha256` 隔离保存。没有保存项目时,刷新后需要重新选择目录和报告。磁盘文件改变后,应重新选择目录;页面内存中的副本可能仍是先前选择时的快照。

## 数据目录

项目、标注、修复草稿、布局与连线补丁都保存在程序同级的 `data/` 目录(默认;可用 `config.json` 或 `--data-root` 改到其它位置),网页不再使用浏览器存储。换浏览器、换端口或清空浏览器数据都不影响这些内容。目录结构:

```text
data/
├── projects/<哈希>/project.json + files/<相对路径>   项目快照(含整包资料字节副本)
├── registry/<哈希>/                                  已登记资料包副本
└── drafts/{annotations,repairs,layout,node-patch}/<哈希>.json   四类草稿
```

目录名是资料包身份(`bundleId + manifestSha256`)的哈希,网页列表里显示的仍是原始 id 与名称。删除项目或删除登记项只移除数据目录里的副本,不触碰原始 F8 导出目录。网页只探测 `/api/session` 判断存储是否可用,不可用时提示原因并降级为只读浏览。

### 升级说明

旧版把项目放在浏览器 IndexedDB、把草稿放在 localStorage,这些数据不会自动迁移到数据目录。升级后需要重新选择资料包并保存一次项目,旧浏览器数据可自行清理。

## 本地项目

点击顶部「项目」或导入窗口的「打开已保存项目」。加载资料后填写项目名,点击「保存当前审查」,会把完整资料、当前/前版报告、作者标注、布局和修复草稿写入数据目录;未保存的编辑也会一并收集。保存成功后当前视图立即转为该项目,无需重新打开;选区、阅读位置和撤销历史保留。下次打开网页,从项目列表点击「打开」即可继续,无需再选文件。修改后需再次保存项目,才能更新此项目的快照。

同一批资料对应一个项目,可改名、更新或删除。删除只移除数据目录里的项目副本,原始 F8 导出目录不变。项目打开前会重新核验文件哈希、报告来源、标注和修复草稿;失败保留当前视图。保存失败会保留旧项目并提示原因。旧项目没有修复字段时按空清单打开;打开项目会恢复显式保存时的草稿快照。

项目只按资料身份(`bundleId + manifestSha256`)唯一,数据目录里的副本与浏览器、端口无关,换浏览器或清空浏览器数据后仍可打开。仍建议保留原 F8 包和报告,并分别导出标注 JSON、修复 JSON 作为备份。网页不保存磁盘目录访问授权,也不自动读取磁盘上的新导出。

同一对话框下方是「已登记资料包」区块:点「登记资料包」选择一次目录,服务端核验整包后复制进数据目录;此后列表一直可见,下次启动或换浏览器后都能从列表直接点「打开」,不必再选目录。登记项显示占用,操作有「打开」与「删除登记」;删除只移除数据目录里的副本,原始导出目录不变。校验失败的资料包会被拒绝并给出原因,数据目录不留半份副本。打开的登记项按包身份(`bundleId + manifestSha256`)与「选择本机目录」共用同一份标注、修复、布局与连线补丁草稿;登记区不保存报告与前版报告,打开后报告为空,状态栏会提示如需保留报告与编辑请另存为项目。

首次打开旧资料会沿用游戏里作者的节点排布；已有网页保存布局优先。新 F8 包含 exact geometry 时，单一节点池直接使用游戏矩形和原生位置，点击「恢复游戏布局」回到该几何位置；「自动排列」仍可撤销。旧包没有几何时只保留阅读、标注、修复和连接编辑，精确布局导出需重新 F8 后更新资料包。网页不会把旧二倍坐标直接当作 EC 坐标混用。

## 作者标注与交接

选择节点后点击「编辑与补丁 → 作者标注」，在「标注内容」用胶囊控件填写主线/支线、所属分组、阶段、完成状态与 Part 独立备注:输入文本回车新建,或从下拉胶囊选择已有值,已选以胶囊显示,点 × 移除。一个 Part 可属于多个分组,阶段只有一个。组共用备注单独编辑，同组 Part 都能看到。节点左上角显示「注」及分组名，完整组名也可悬停查看；右上角的问题标记属于审查报告。

「审查范围」「标注内容」「已有标注」用三个按钮切换，不清除正在编辑的内容。可收起编辑面板继续操作节点池；从顶部重新打开或点击另一个节点的作者标记时，切换到该选区并保留原草稿。「已有标注」包含当前草稿,可按分组筛选;每项默认收起,展开查看组备注与 Part 独立备注。

Ctrl 多选或框选后可批量填写;只修改勾选字段,未勾选备注保持原样。批量设置所属分组会替换选中节点的分组集合。点击「保存全部编辑」把各页面与各选区的草稿写入数据目录;仅切换、最小化或关闭窗口不会清除草稿,刷新网页前仍需保存。

「导出标注 JSON」和「下载 AI 交接说明」会先收集并保存当前全部编辑，再下载 JSON 或可读 Markdown；JSON 包含当前节点布局。交给外部 AI 时同时提供原 F8 包、`author-annotations.json`、`author-handoff.md` 和 `ec-scene-review` skill 文件夹。标注与原证据分开传递，不能用作者意图代替脚本事实。

导入同批次标注会替换当前作者标注，并恢复文件所附布局；可提前导出备份。错批次、未知节点或坏格式会被拒绝，当前内容保留。新批次请使用下述「更新资料包」，直接导入仍严格检查来源。格式见 [作者标注格式](../ec-scene-review/Reference/annotations-format.md)。

## 更新资料包

打开原项目，点击「项目 → 更新资料包」，选择新的完整 F8 导出目录。先查看匹配、新增、删除、变化与草稿冲突，再确认保存并打开新项目；取消不会替换原视图。原项目保留，新包已有项目时拒绝覆盖。

同 UID、同类型节点保留分组、备注、阶段、状态和网页位置；新增节点采用新包位置。文本、结构或相关连线变化会列为待复核，删除和类型冲突节点的旧内容保留在记录中。分组定义与组备注继续保留，审查范围需结合变化重新检查。

修复草稿重新检查位置与原文；节点结构或文本发生变化时保守隔离，冲突项不会进入可导出的应用清单。已达到目标文本的条目不重复应用。旧 AI 报告保存在历史记录，新包当前报告为空，需要重新审查。

从「项目 → 迁移记录」查看旧标注、冲突草稿和历史报告。可在现有编辑入口重新整理，或明确放弃记录；处理状态在保存、重开及再次迁移后保留。已有旧项目不会被未保存编辑覆盖，这些编辑会随本次迁移保存在新项目的历史快照中。

## 修复草稿

1. 点击 CUT 查看全文，在具体文本框的布局旁点击「编辑修复」。左侧保留只读原文，右侧修改整段对白及其中的脚本；多布局分别编辑，不推定游戏当前使用哪份布局。
2. 「前后差异」用红色显示替换前的行、绿色显示替换后的行。较长差异会省略部分行，完整内容仍保留在上方和导出文件中。
3. 输入自动记录并写入数据目录;关闭或切换编辑对象保留有效草稿。清空新文表示改为空文本,「恢复原文」会移除该项。编辑页顶部一条工具行,从左到右是「恢复原文」「保存」「返回」,没有底栏;保存只写数据目录草稿,不关闭编辑页。
4. 「编辑与补丁 → 修复清单」每项默认收起,标题旁是「定位/继续编辑/移除」操作组;展开才显示原文与新文。可导出 `ec-scene-repair-plan.json`。导入会整体替换当前清单；错来源、错位置、原文失配或重复条目整份拒绝，当前草稿保留。

网页不修改游戏；导出的清单在游戏内修复窗口直接应用，缺失目标按项跳过，仅写内存，保存 Scene 仍由作者决定。原 CUT 阅读、节点连线和报告问题标记继续反映 F8 原证据；页面不执行或验证新脚本的运行结果，不编辑外部依赖文件。没有原始文本或索引的布局只读。

草稿按资料包身份保存在数据目录,重新选择同包可恢复;保存项目时也会一并收集。输入超出每项 1,000,000 字符或整份 1000 项的限制时会提示,并保留当前输入供调整。服务端存储失败会明确提示,当前有效草稿仍可导出备份。格式见 [修复清单格式](repair-plan-format.md)。

## 节点连接、EC 布局与 goto 预览

加载资料后点击顶部「编辑与补丁」，在「节点补丁」页签修改连接。右键节点或普通边可搜索目标；选中普通边后也可拖动目标端点，释放到有效节点才写入。选中节点时，面板同时列出可用空出口槽，可为空槽选择目标并新建连接。候选保留系统节点并排除来源自身；空白、Esc、来源自身、脚本边、不可用槽和未知目标不会改补丁。节点、选项和输出槽数量不变，条件、计数与淡入淡出参数保持原样。「导出补丁」下载独立的 `ec-scene-node-patch` 文件，游戏端仍会重新核验；网页修改不会自动应用到游戏。

新 F8 包提供完整几何时，单一节点池使用游戏节点矩形。普通连接始终右出左入，右侧出口按数量等距分布，自上而下对应选项顺序。脚本跳转从底部按数量分布并保留虚线；未收录目标也占一个出口，只画向下短线。所有入线共用目标左侧中心，H Part 用粉色边框。无几何旧包按默认节点尺寸使用同一端口规则。

箭头位于目标边界外，标签避让节点与其它标签。选中普通边可拖动绿色路线控制点调整曲率，不移动端点；排列菜单可恢复自动路线。路线随数据目录草稿与项目保存，不进入游戏补丁；不做全图避障，也不自动整理原有重叠节点。画布大小用固定下拉选择(原游戏原始画布或 1~10 倍),修改立即刷新范围框。

框选时节点高亮和选中数量实时更新，连接与标注面板在松手或取消后同步。拖动路线控制点只重算当前边，提交、取消或撤销后统一调整标签位置。

选中集合外框只移动显式选中节点。对齐至少两个节点，可选选区边界或一个选中节点为基准；等间隔至少三个节点，按矩形边缘计算。间隔留空时优先保留原首末跨度，空间不足时按最小 24 展开；显式间隔可设为 0 或正数。悬停/聚焦排列按钮预览，离开取消，点击提交。节点拖动显示参考线，吸附可关闭，也可按 Alt 临时禁用。

布局、连接、画布和网页路线共用撤销/重做，支持 Ctrl+Z、Ctrl+Shift+Z、Ctrl+Y；输入框保留原生文本撤销。一次操作对应一条历史，最多 20 条，新操作清除重做。面板默认显示当前选区，可切换全部/仅已修改并搜索；修改清单显示原值与新值，支持定位与单项恢复。

画布工具栏的眼睛按钮循环切换连线显示：睁眼全部显示，半睁只隐藏脚本跳转，闭眼隐藏全部；线上标签随连线一起隐藏，不改变任何数据。画布工具栏的保存按钮分两种形态：打开项目或首次保存项目成功后是软盘图标，点击等同「项目 → 保存当前审查」，以当前项目名更新快照；尚未保存为项目时是铅笔图标，只把布局与连线等草稿写入数据目录，不建项目。要首次保存整包、报告与标注，使用「项目 → 保存当前审查」。

页脚显示「尚未保存为项目」「项目已保存」或「项目有未保存修改」。平移、缩放、适配和选择节点不算内容修改;平移仍保存相机草稿。内容编辑、替换或清除已核验报告立即提示未保存;同内容报告重读不算修改。保存期间继续编辑,保存完成后仍提示未保存,需再次保存;保存失败不改变当前项目名。

「恢复原始连接」保留位置，「恢复游戏布局」保留连接，「清除全部」恢复两者并清除网页路线，均保留当前画布尺寸并可撤销。导入补丁先弹出独立预览窗口显示替换范围,点击应用后才修改。连接-only 导入保留当前位置和画布。页脚分别显示草稿、项目快照和补丁导出状态。

节点补丁随项目保存、重开。项目重开以保存的单一节点布局和画布范围为准，旧布局补丁不会覆盖后来的自动排列或原生恢复；连接-only 补丁只改连接，不移动节点。更新资料包后旧节点补丁保留为待复核记录，可查看或下载原文件；请在新资料中重新创建，不能直接改来源后应用。

旧项目若含普通连接指向自身的草稿，恢复时保留合法连接和布局，将完整旧补丁放入待复核区供查看、下载；不会激活旧自连。保存重开和更新资料包继续保留该快照，其它格式或来源错误仍拒绝。脚本 goto 自跳不受普通连接限制；点击脚本边打开包含命令的源 CUT 全文，再从文本修复入口修改。

CUT 的修复草稿会同步更新 goto 静态预览，恢复原文或移除草稿后恢复原始跳转。预览区分普通连接、草稿跳转及不完整候选；动态值、同名目标、缺失落点和无效脚本会提示。它展示脚本声明和候选目标，不保证运行时一定走该路线；旧报告和 F8 原文保持不变。

## 模块职责

- `src/files.mjs`：用户文件选择、复用 review-core 校验、并发选择代次。
- `src/model.mjs`：真实节点/CUT/普通连接适配；原始数组位置与源索引分开。
- `src/scripts.mjs`：读取摘要的结构化步骤，解析外部 XML；不执行脚本。注释与字符串不作为命令。
- `src/locations.mjs`：标准引用、摘要原文及共享依赖调用点映射。
- `src/ui/`:节点池、两层问题面板、CUT 阅读、状态与布局;`state.js` 的 `createState(data, draft)` 接受 `mountView` 前预取的草稿,仍是同步函数。
- `src/ui/editor-panel.js`、`toolbar.js`：停靠宿主与工具栏；`connection-edit.mjs`、`layout-actions.mjs`：连接草稿、对齐/等间隔/吸附纯计算；`edge-geometry.mjs`：局部路径与标签放置。
- `src/web-layout.mjs`：网页路线偏移核验，独立于游戏补丁。
- `src/annotations.mjs`、`src/ui/annotations.js`:分别负责作者标注格式/核验/交接与编辑对话框;读写走 `/api/drafts/annotations`。
- `src/annotation-drafts.mjs`、`src/ui/annotation-fields.js`：负责跨选区字段草稿与分组/阶段控件。
- `src/api.mjs`:前端唯一的服务端入口;URL 前缀、JSON 编解码、字节 base64 往返与错误归一化都在这里。
- `src/projects.mjs`、`src/ui/projects.js`:负责项目整包复核和项目列表/资料包登记对话框;存储调用转发给 `src/api.mjs`。
- `src/node-patch-recovery.mjs`:恢复旧自连草稿,分离合法活动补丁与完整待复核快照,供项目和草稿存储共用。
- `src/migration*.mjs`、`src/ui/migration.js`：负责跨包匹配与草稿重核、迁移记录验证，以及预览、确认和历史查看。
- `src/repairs.mjs`、`src/ui/repairs.js`:分别负责修复清单的精确定位/核验,以及文本编辑、差异与导入导出;读写走 `/api/drafts/repairs`。
- `src/ec-layout.mjs`、`src/node-patch.mjs`：分别负责 frame/native 可逆转换、完整画布校验和节点补丁格式/原生 before-after；`src/ui/graph-render.js`、`gestures.js`、`frame-queue.js` 负责复用图元素、鼠标/键盘手势和按帧合并更新。单一节点池不使用双模式或复杂避障状态。
- `server/`:本机服务。`main.mjs` 路由与启动,`http.mjs` 请求体解析与回环校验,`paths.mjs` 配置与目录映射,`store.mjs` 项目与登记,`drafts.mjs` 四类草稿,`verify.mjs` 哈希与清单核验,`assets.mjs` 静态资源,`atomic.mjs` 原子写。
- `scripts/`:esbuild 静态构建与 `--exe` 打包入口。

完整证据和摘要沿用 `../review-core/`。不把 `node-files.mjs` 打包进网页,也不在浏览器另写来源或引文核验规则。服务端 `/api/` 契约见 `.trellis/spec/frontend/scene-review-local-service-contract.md`。

## 阅读边界

普通连线保留导出中有目标的出口，包括原始 `NotUsed` 出口，路线文字会注明未启用。脚本连线是静态候选，不表示必然执行。动态目标、重名目标、未知 CUT、循环和缺口明确停止；不根据相似名称补目标。Start/End 等系统节点保留，系统节点没有对白。

选项按 review-core 的 `optionMappings` 映射，不能由 `sortOrder` 猜槽位。CUT 显示源序号，报告 JSON Pointer 按真实数组位置解析。全文展示全部布局原文，不推定哪份布局当前可见、不猜说话人。脚本/标签只显示为文本。

外部脚本按游戏规则解读：正文必须自带字面小写 `<script>…</script>`，否则游戏按普通文本处理、不执行也不报错，页面同样不展开跳转关系并给出提示，不会替文件补包装。

用户可读性确认仍需实际试用。引用核验通过不代表报告结论正确或游戏问题已修复。
