# EC_SceneAutoSave

在 HEdit 场景编辑中，空闲时只把改动过的内容写进自动保存会话，不重写整个场景。游戏崩溃或误关后，先原生读同一个存档，再在面板里把会话应用回去。

## 使用

1. 原生读档后自动保存开始。新建的场景要先原生保存一次。
2. 正常编辑。停止操作 10 秒后自动记录一次，两次记录至少间隔 180 秒。面板里的"立即保存"不受间隔限制。
3. 恢复：原生读同一个存档 → 有可恢复会话时面板自动打开 → 在节点总览点"应用"，再点"确认应用"。
4. 原生保存后以新文件为基准重新开始；覆盖保存时，该存档旧的自动保存会话失效并被清理。
5. 点试玩前会先记录一次，试玩返回后继续写同一个会话。

## 面板（默认 F4）

- 状态、基准存档、当前会话、上次自动保存写入的 Part 数、大小与耗时。
- 下次自动保存的等待原因：空闲倒计时、间隔倒计时、暂缓原因（拖动中、输入框输入中、窗口打开中等）。
- 可恢复会话列表：更新时间、改动的 Part 数、换过的角色数，以及节点图、地图、场景信息是否改过。不能应用时显示原因。

## 记录范围

| 内容 | 粒度 |
|---|---|
| ADV / H Part | 整个 Part；只写打开过且内容变化的 Part，以及新增、复制出的 Part |
| 节点位置与连线 | 整张节点图，变化时写 |
| 地图 | 全部地图，变化时写 |
| 场景信息（标题、说明、标签、BGM 等） | 变化时写 |
| 角色 | 换卡后写该角色的整张卡 |

不记录：场景缩略图、节点画布的平移与缩放、其它插件通过 ExtendedSave 写在场景级的扩展数据。

## 限制

- 只能应用到刚读档、尚未改动的场景。只打开 Part 看过、没有改内容不算改动。
- 新场景、试玩临时文件、教程不自动保存。
- 每个存档默认保留最近 3 个会话。
- 应用到一半失败时自动保存暂停，需要重新读档后再试；存档文件和会话文件都不会被改动。

## 存储

`UserData/edit/autosave/sessions/<存档名>_<路径哈希>/<时间>/`，内含 `manifest.xml` 与 `.bin` 数据文件。原生读档窗口只扫描 `edit/scene`，不会显示这些文件。卸载插件后可以直接删除 `UserData/edit/autosave/`。

## 配置

`BepInEx/config/com.rainbowing.ec.sceneautosave.cfg` 或 F1 插件设置：

| 键 | 默认 | 说明 |
|---|---|---|
| General / Enabled | true | 空闲时自动记录 |
| General / Idle Seconds | 10 | 无操作多少秒后触发，3~120 |
| General / Min Interval Seconds | 180 | 两次自动保存的最短间隔，30~3600 |
| General / Sessions Per Scene | 3 | 每个存档保留的会话数，1~10 |
| Window / Toggle Key | F4 | 打开或关闭面板 |
| Window / Position X、Y | 0.98、0.12 | 面板位置，0~1 |

## 兼容

- 不修改原生保存与读档流程，不写 png 存档。
- 软依赖 `EC_BatchTextReplace`：批量替换改到的 Part 也会被记录。
